# Project: IntelliWaste – Synthetic Data Generation, LSTM Training and Complete Prediction Pipeline

Act as a Senior Machine Learning Engineer and Python Developer.

Build a simple, working prototype of **IntelliWaste**, an AI-based waste-management system that predicts bin fill levels using an LSTM model, requests citizen verification when prediction confidence is low, combines both estimates using reliability-based data fusion, and independently classifies waste using ResNet50.

The implementation must follow the methodology and mathematical formulations specified below.

Do not introduce unnecessary algorithms, complicated mathematical formulations, or additional modules.

## 1. Main Objectives

The implementation must perform the following tasks in sequence:

1. Generate realistic synthetic historical data for at least 10 waste bins representing a medium-sized city area.
2. Train an LSTM model using the generated historical data.
3. Evaluate the trained LSTM model.
4. Predict the future fill level for each bin.
5. Calculate prediction confidence.
6. Request citizen verification when confidence is below 80%.
7. Simulate or collect citizen-selected fill categories.
8. Calculate Citizen Reliability Scores (CRS).
9. Combine LSTM and citizen fill estimates using reliability-based data fusion.
10. Calculate the final estimated fill level and time-to-full.
11. Process citizen-submitted photographs independently using ResNet50 for waste classification.
12. Display all results in a simple, understandable format.

**Important restrictions:**

- Do not use physical IoT sensors.
- Do not implement Method B (photo-based fill estimation).
- Do not calculate fill percentage from photographs.
- Do not include overflow probability or overflow probability calculations.
- Do not use photographs as a source for fill-level fusion.
- ResNet50 must only classify waste into Organic, Recyclable, and E-waste.
- Use Method A: Citizen selects a fill category.
- Use only two sources for fill-level fusion: LSTM and citizen reports.

## 3. LSTM Model – Training and Prediction

### A. Input Features

The LSTM model must use the historical observations of each bin.

Define the input sequence as:

\[
X_{i,t}=[F_{i,t-1},F_{i,t-2},...,F_{i,t-L},
h_t,d_t,m_t,z_i,G_{i,t}]
\]

Where:

- \(i\) = Bin identifier.
- \(t\) = Current prediction timestamp.
- \(F_{i,t-1},F_{i,t-2},...\) = Previous fill-level observations.
- \(L\) = Historical sequence length.
- \(h_t\) = Hour of observation.
- \(d_t\) = Day of the week.
- \(m_t\) = Month.
- \(z_i\) = Bin location type.
- \(G_{i,t}\) = Historical waste accumulation rate.

For implementation, use a sequence length of 24 hours.

The actual LSTM input must be a sequence matrix of shape:

`(24, number_of_features)`

Use suitable numerical encoding for time and location features. For example, use cyclical encoding for hour and weekday, and one-hot encoding for zone type.

### B. Prediction Target

The model must predict the bin's fill percentage at the next hourly observation.

Define:

\[
F_{v,i,t}=LSTM(X_{i,t})
\]

Where:

- \(F_{v,i,t}\) = LSTM-predicted fill level for bin \(i\) at target timestamp \(t\).
- \(X_{i,t}\) = Historical input sequence.

Keep the predicted fill level between 0% and 100%.

The citizen's reported fill level must refer to the same bin and approximately the same target timestamp as the LSTM prediction. Do not combine estimates belonging to different bins or substantially different observation times.

### C. LSTM Architecture

Use a straightforward LSTM architecture:

```text
Input Layer
    |
LSTM Layer (64 units, return_sequences=True)
    |
Dropout (0.2)
    |
LSTM Layer (32 units)
    |
Dense Layer (16 units, ReLU)
    |
Dense Layer (1 unit, Sigmoid)
    |
Predicted Fill Percentage
```

Scale the target fill percentage to the range 0–1 during training and convert the model output back to 0–100%.

### D. Model Training

Use TensorFlow/Keras.

Recommended configuration:

| Parameter | Value |
|---|---|
| Lookback sequence | 24 hours |
| Forecast horizon | 1 hour |
| First LSTM layer | 64 units |
| Second LSTM layer | 32 units |
| Dropout | 0.2 |
| Optimizer | Adam |
| Loss function | Mean Squared Error |
| Epochs | Up to 50 |
| Batch size | 32 |
| Early stopping | Enabled |

Split the dataset chronologically:

- 70% Training.
- 15% Validation.
- 15% Testing.

Perform the split separately by bin or by chronological time boundaries across bins.

Do not randomly split overlapping time-series windows.

Fit preprocessing scalers using training data only.

Save the trained model as:

`intelliwaste_lstm.keras`

### E. Model Evaluation

Evaluate the LSTM using MAE and RMSE.

Mean Absolute Error:

\[
MAE=\frac{1}{N}\sum_{i=1}^{N}|F_i-\hat F_i|
\]

Root Mean Square Error:

\[
RMSE=\sqrt{\frac{1}{N}\sum_{i=1}^{N}(F_i-\hat F_i)^2}
\]

Where:

- \(N\) = Number of test observations.
- \(F_i\) = Actual fill percentage.
- \(\hat F_i\) = LSTM-predicted fill percentage.

Report both metrics in percentage points.

Use validation MAE for the confidence and reliability calculations below. Use test MAE and RMSE only for final model evaluation.

## 4. Prediction Confidence Calculation

The system must calculate prediction confidence using the validation error.

Define a configurable maximum acceptable prediction error:

\[
E_{\max}=10
\]

Where the unit is percentage points.

Calculate normalized uncertainty:

\[
U_v=\min\left(1,\frac{MAE_{val}}{E_{\max}}\right)
\]

Calculate confidence:

\[
\boxed{C_v=1-U_v}
\]

Where:

- \(MAE_{val}\) = Validation MAE in percentage points.
- \(E_{\max}\) = Maximum acceptable prediction error.
- \(U_v\) = Normalized prediction uncertainty.
- \(C_v\) = Prediction confidence, between 0 and 1.

This is a simple validation-error-based confidence score, not a statistically calibrated probability.

Use a configurable threshold:

\[
\theta=0.80
\]

Decision:

```text
IF C_v < 0.80:
    Request citizen verification

ELSE:
    Retain the LSTM prediction
```

Calculate confidence separately for each bin using its validation prediction errors where sufficient validation observations are available. Otherwise, use the overall validation MAE and clearly label it as a global confidence score.

## 6. Citizen Reliability Score (CRS)

Generate a separate synthetic history of previously verified reports for each demo citizen.

Use at least 20 previous reports per citizen.

Each historical citizen report must be compared with the independently generated actual bin fill level at the corresponding timestamp.

For the prototype, define a report as correct when the absolute difference between the citizen's reported fill level and the independently verified actual fill level is no more than 10 percentage points.

Calculate:

\[
\boxed{CRS=\frac{N_{correct}}{N_{verified}}}
\]

Where:

- \(N_{correct}\) = Number of correctly verified citizen reports.
- \(N_{verified}\) = Total number of verified reports.

CRS must be between 0 and 1.

For example, if 18 out of 20 reports are correct:

\[
CRS=\frac{18}{20}=0.90
\]

Important:

- Calculate CRS from previously verified reports only.
- Do not count the current citizen submission as correct before independent verification.
- Do not use the final fused result as ground truth for calculating CRS.
- If a real citizen has no verified history, mark the CRS as unavailable rather than inventing a score. Do not use that report in reliability fusion until a valid reliability estimate is available.

Save the generated history as:

## 7. Reliability-Based Data Fusion

The system must combine only two fill-level sources:

1. LSTM prediction.
2. Citizen-reported fill level.

Do not include a photo-based fill estimator.

### A. Calculate Virtual Sensor Error

Convert validation MAE from percentage points to a normalized 0–1 scale:

\[
e_v=\frac{MAE_{val}}{100}
\]

Where:

- \(e_v\) = Normalized LSTM error.
- \(MAE_{val}\) = Validation MAE in percentage points.

### B. Calculate Citizen Error Proxy

Calculate the citizen error proxy using CRS:

\[
e_c=1-CRS
\]

Where:

- \(e_c\) = Citizen error proxy.
- \(CRS\) = Citizen Reliability Score.

### C. Calculate Source Reliability

Use:

\[
R_v=\frac{1}{e_v+\epsilon}
\]

\[
R_c=\frac{1}{e_c+\epsilon}
\]

Where:

- \(R_v\) = LSTM reliability.
- \(R_c\) = Citizen reliability.
- \(\epsilon=0.001\) = Small constant to prevent division by zero.

### D. Normalize Reliability Weights

Calculate:

\[
w_v=\frac{R_v}{R_v+R_c}
\]

\[
w_c=\frac{R_c}{R_v+R_c}
\]

The weights must satisfy:

\[
w_v+w_c=1
\]

### E. Calculate Final Fill Level

Use the two-source weighted fusion formula:

\[
\boxed{F_{final}=w_vF_v+w_cF_c}
\]

Where:

- \(F_v\) = LSTM-predicted fill percentage.
- \(F_c\) = Citizen-reported fill percentage.
- \(w_v\) = LSTM reliability weight.
- \(w_c\) = Citizen reliability weight.
- \(F_{final}\) = Final estimated fill percentage.

If citizen verification is not requested, not received, or does not have a valid CRS, retain the LSTM prediction:

\[
F_{final}=F_v
\]

Important: Both source estimates must refer to the same bin and target timestamp.

The citizen error formula is an error-rate proxy based on historical report correctness. Document this limitation and do not describe the two reliability values as independently calibrated probabilities.

## 8. Time-to-Full Calculation

Calculate the historical fill accumulation rate using two consecutive valid observations with no collection event between them.

\[
\boxed{G_t=\frac{F_2-F_1}{t_2-t_1}}
\]

Where:

- \(F_1\) = Earlier fill level.
- \(F_2\) = Later fill level.
- \(t_1,t_2\) = Corresponding observation times.
- \(G_t\) = Fill accumulation rate in percentage points per hour.

Use the final fused fill level to calculate the time remaining until the bin reaches 100%.

\[
\boxed{T_{full}=\frac{100-F_{final}}{G_t}}
\]

Where:

- \(F_{final}\) = Final estimated fill percentage.
- \(G_t\) = Historical filling rate.
- \(T_{full}\) = Estimated time-to-full in hours.

Also calculate the initial LSTM-only time-to-full:

\[
T_{initial}=\frac{100-F_v}{G_t}
\]

Display both values to show how citizen verification changes the estimated time-to-full.

If the historical accumulation rate is zero or negative, display `Time-to-full: Not estimable` instead of inventing a result.

Assume a constant accumulation rate for this calculation and clearly state that it is an approximation.

Do not calculate overflow probability.

The three output classes must be:

1. Organic.
2. Recyclable.
3. E-waste.

The prediction rule is:

\[
\boxed{\hat W=\arg\max_k P(W=k|I)}
\]

Where:

- \(I\) = Citizen-submitted photograph.
- \(W\) = Waste category.
- \(P(W=k|I)\) = Probability of category \(k\).

The photograph must only be used for waste classification.

Never use ResNet50 probabilities to calculate fill percentage.

Do not use an unfine-tuned ImageNet ResNet50 head as though it were a trained waste classifier.

- Allow an image path and model checkpoint to be supplied later.
- Clearly display `ResNet50 classifier not configured`.
- Do not invent classification probabilities or claim classification accuracy.
